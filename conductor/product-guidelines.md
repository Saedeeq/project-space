# Product Guidelines

## Prose Style
- **Clear and Direct:** Use concise, action-oriented language
- **Technical Precision:** Prefer specific technical terms over vague descriptions
- **Consistent Voice:** Maintain a professional yet approachable tone
- **Active Voice:** Write in active voice for clarity and accountability

## Branding Guidelines
- **Visual Identity:** Clean, modern, developer-focused aesthetic
- **Color Palette:** Use Tailwind's default palette with consistent semantic naming
- **Typography:** Leverage Next.js font optimization with Geist font family
- **Iconography:** Use Heroicons consistently throughout the application

## UX Principles
1. **Progressive Disclosure:** Show essential information first, reveal details on demand
2. **Consistent Patterns:** Use established UI patterns for familiar interactions
3. **Feedback First:** Always provide immediate feedback for user actions
4. **Accessibility:** Maintain WCAG 2.1 AA compliance for all interactive elements
5. **Mobile-Responsive:** Design mobile-first, enhance for larger screens

## Content Guidelines
- **Headers:** Use sentence case for UI elements, title case for documentation
- **Labels:** Be specific and action-oriented (e.g., "Create Project" not "New")
- **Error Messages:** Explain what went wrong and how to fix it
- **Empty States:** Provide context and next steps for empty views

## Code Documentation
- **Component Docs:** Each component should have a brief description of its purpose
- **Function Comments:** Document *why*, not *what* (code shows what)
- **Type Definitions:** Use TypeScript interfaces for all data structures
- **API Contracts:** Document request/response shapes for all API endpoints
